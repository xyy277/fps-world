# 单页 FPS 功能上限调研报告

> 调研时间：2026-07-30
> 适用项目：方块枪战（Block FPS）—— 单 HTML 文件 + CDN 加载 Three.js + 零后端
> 调研目标：在「单页、零依赖安装、即开即玩」的硬约束下，评估 FPS 游戏可集成的功能全集与理论上限，并给出分阶段实施路线。

---

## 1. 调研背景

方块枪战定位为**单页体素风第一人称射击游戏**，部署于 GitHub Pages + Cloudflare Pages，必须保持「单 HTML 文件、CDN 加载 Three.js、开箱即玩」的形态。在初版完成基础玩法后，需要评估：

- FPS 游戏还需要哪些功能？
- 单页 HTML 最大能集成哪些功能？
- 最大目标能做到什么程度？

本报告回答上述问题，并作为后续多 Agent 分阶段开发的依据。

---

## 2. 技术约束分析

### 2.1 硬约束（不可突破）

| 约束 | 说明 | 影响 |
|------|------|------|
| 单 HTML 文件 | 所有 HTML/CSS/JS 内联，不拆分多文件 | 代码需区段化组织，单文件冲突防护 |
| CDN 加载 Three.js r128 | 不走 npm/bundler，`<script>` 直引 | 不能用 ES Module 三方库，仅能用全局 `THREE` |
| 无构建步骤 | 禁止 `npm install` / webpack / vite | 不能用 TypeScript、JSX、Sass，纯原生 ES5+ |
| 无后端 | 纯静态托管，无服务器逻辑 | 排行榜/多人/存档同步只能走 localStorage 或第三方 BaaS |
| 无图片/音频资源 | 纹理 Canvas 程序化生成，音效 Web Audio 合成 | 资源体积趋近于零，但表现力受限于程序化能力 |
| 移动端优先 | 必须支持触屏单机游玩 | 所有交互需双套输入（键鼠 + 触屏） |

### 2.2 软约束（可权衡）

- **性能**：移动端 GPU/WebGL 能力有限，draw call 与粒子数需控制。
- **包体积**：单文件越大加载越慢，建议控制在 5000 行以内（当前 2274 行）。
- **可维护性**：单文件多人协作易冲突，需严格区段标注 + 串行写入。

## 3. 功能维度分析

按 8 个维度评估可集成的功能全集，标注**可行性**（✅ 已实施 / 🟡 可做 / 🔴 受限或不宜）。

### 3.1 渲染（Render）

| 功能 | 可行性 | 说明 |
|------|--------|------|
| 体素地形程序化生成 | ✅ | Simplex/Value 噪声 + 区块网格 |
| 程序化纹理（Canvas 2D） | ✅ | 16×16 像素图集，无图片资源 |
| 动态光照（方向光 + 环境光） | ✅ | Three.js DirectionalLight + AmbientLight |
| 昼夜循环 | ✅ | 光色/强度/雾色随时间插值 |
| 阴影贴图 | 🟡 | 性能开销大，仅高画质档开启 |
| 后处理（泛光/景深/SSAO） | 🟡 | r128 需手动引入 EffectComposer，增加 CDN 依赖 |
| 体积雾 / 体积云 | 🟡 | ShaderMaterial 可实现，移动端慎用 |
| 天气系统（雨/雪/雾） | 🟡 | 粒子系统模拟，与昼夜联动 |
| 水面着色器 | 🟡 | 简单波动 + 折射近似可行 |
| 反射（SSR/立方体贴图） | 🔴 | 性能代价过高，单页不宜 |
| 光线追踪 | 🔴 | 浏览器支持有限，违背移动端优先 |

**上限**：体素世界 + 动态昼夜 + 程序化纹理 + 可选后处理 + 天气切换，足以逼近 Minecraft 原版视觉。

### 3.2 玩法（Gameplay）

| 功能 | 可行性 | 说明 |
|------|--------|------|
| 多武器系统（步枪/霰弹/狙击） | ✅ | 不同 dmg/rate/spread/pellets |
| 武器后坐力 + 动态散布（bloom） | ✅ | 连发增大、停火恢复 |
| 换弹动画 + 弹匣管理 | ✅ | 枪身下沉旋转 + 弹药计数 |
| 手雷 / 投掷物 | ✅ | 抛物线物理 + 落地引爆 |
| 近战攻击 | ✅ | 扇形命中判定 + 冷却 |
| TNT 连锁引爆 | ✅ | BFS 队列传播 |
| 方块建造/破坏 | ✅ | 射线检测 + 体素增删 |
| 波次生存（丧尸/苦力怕） | ✅ | 计时器刷怪 + 清波回血 |
| 敌人 FSM AI（追击/攻击/逃跑/游荡） | ✅ | 状态机 + A* 寻路 |
| 爆头判定 + 双倍伤害 | ✅ | 命中 Y 坐标判定 |
| 掉落系统（红心/弹药） | ✅ | 概率掉落 + 拾取判定 |
| Boss 战 | 🟡 | 多阶段 + 特殊技能，可行但工作量大 |
| 武器升级/配件（瞄镜/消音/扩容） | 🟡 | UI + 属性叠加 |
| 载具（车/船） | 🟡 | 物理简化可行，体素风格适配 |
| 技能/主动技能（冲刺/护盾/时停） | 🟡 | 冷却 + 临时状态修改 |
| 多人联机 | 🔴 | 需 WebRTC + 信令服务器，违背「无后端」 |
| 程序化关卡生成 | 🟡 | 噪声 + 规则拼接，体素天然适配 |
| 任务/目标系统 | 🟡 | 击杀 N 个/到达地点/护送 |

**上限**：单机 PVE 波次生存 + 完整武器库 + Boss + 技能 + 升级树，可做到接近《像素僵尸危机》系列的玩法深度，但无法实现真多人联机。

### 3.3 音频（Audio）

| 功能 | 可行性 | 说明 |
|------|--------|------|
| Web Audio 程序化音效 | ✅ | Oscillator + Gain 合成枪声/脚步/爆炸 |
| 音量主控 + 记忆 | ✅ | masterGain + localStorage |
| 空间音效（3D 定位） | 🟡 | PannerNode 可做，移动端开销中 |
| 背景音乐（BGM） | 🟡 | 程序化循环旋律或序列化音符，无音频文件 |
| 动态音乐（战斗/探索切换） | 🟡 | 状态驱动音色/节奏切换 |
| 语音对话 | 🔴 | 需 TTS 资源或录制，违背无资源约束 |

**上限**：全程序化音效 + 简单 BGM + 动态切换，零音频文件。

### 3.4 UI/UX

| 功能 | 可行性 | 说明 |
|------|--------|------|
| HUD（血量/弹药/得分/波次） | ✅ | DOM + CSS |
| 动态准星（随 bloom 扩大） | ✅ | CSS 尺寸插值 |
| Hitmarker（命中/爆头反馈） | ✅ | 颜色区分 |
| 伤害数字（DOM 池） | ✅ | 3D→2D 投影 + 上浮淡出 |
| 击杀提示（Killfeed） | ✅ | 限定 5 条，自动淡出 |
| 小地图 | ✅ | Canvas 2D 绘制，每 3 帧刷新 |
| 计分板（武器分布/连杀） | ✅ | 局末表格 |
| 设置面板（画质/音量/灵敏度） | ✅ | 滑块 + select |
| 进度/成就墙 | ✅ | DOM 网格 |
| 升级面板 | ✅ | 按钮组 + 技能点 |
| 触屏控件（方向键/动作键/滑动视角） | ✅ | pointer events |
| 暂停/菜单/游戏结束界面 | ✅ | overlay |
| 教程/引导 | 🟡 | 首次进入高亮提示 |
| 多语言（i18n） | 🟡 | 字典切换，工作量中 |
| 主题切换（明/暗/像素风） | 🟡 | CSS 变量 |

**上限**：完整 HUD + 反馈系统 + 设置 + 进度 + 触屏适配，可达商业手游 UI 水准。

### 3.5 输入（Input）

| 功能 | 可行性 | 说明 |
|------|--------|------|
| 鼠标 + 键盘（WASD/Shift/空格/R/Q/F/1-6） | ✅ | keyCode 映射 |
| Pointer Lock（鼠标锁定） | ✅ | requestPointerLock |
| 鼠标滚轮切换武器 | ✅ | wheel 事件 |
| 触屏方向键（多指斜向） | ✅ | touchstart/move/end |
| 触屏滑动视角 | ✅ | 屏幕空白处拖拽 |
| 触屏动作按钮组 | ✅ | 固定位置 tbtn |
| 手柄（Gamepad API） | 🟡 | 标准映射可行，需额外适配 |
| 语音输入 | 🔴 | 需 Web Speech API，噪声环境不可靠 |

**上限**：键鼠 + 触屏双端原生，手柄可选扩展。

### 3.6 进度与存档（Progression）

| 功能 | 可行性 | 说明 |
|------|--------|------|
| localStorage 全局存档 | ✅ | 版本化 JSON |
| 最高记录（得分/波次/击杀/连杀） | ✅ | 局末结算 |
| 成就系统（条件检测 + 通知） | ✅ | 局内实时 + Toast |
| XP / 等级 / 技能点 | ✅ | 升级公式 + 属性点 |
| 升级树（伤害/血量/换弹/移速） | ✅ | 各 5 级，玩法生效 |
| 本地排行榜 | 🟡 | localStorage 多条目排序 |
| 云存档同步 | 🔴 | 需后端或 BaaS，违背无后端 |
| 跨设备存档 | 🔴 | 同上 |

**上限**：本地完整 RPG 化进度系统，但无法跨设备同步。

### 3.7 性能（Performance）

| 功能 | 可行性 | 说明 |
|------|--------|------|
| 画质分级（低/中/高） | ✅ | 雾/阴影/粒子数动态调整 |
| 对象池（粒子/弹道） | ✅ | 减少 GC |
| 区块按需构建 | ✅ | 仅可见区块 |
| 小地图按帧刷新（每 3 帧） | ✅ | 降低 Canvas 绘制频率 |
| 寻路范围限制（A* 10×10 + 500 迭代） | ✅ | 防卡顿 |
| Web Worker 后台计算 | 🟡 | 单文件内 inline Worker 可行，复杂度高 |
| GPU 实例化（InstancedMesh） | 🟡 | 大量同类方块/敌人可行 |
| 纹理图集 | ✅ | 已用 4×4 像素图集 |

**上限**：移动端稳定 30-60 FPS，桌面端 60 FPS，支持百级敌人和千级粒子。

### 3.8 部署（Deployment）

| 功能 | 可行性 | 说明 |
|------|--------|------|
| GitHub Pages（push 即更新） | ✅ | main 分支根目录 |
| Cloudflare Pages（CDN 加速） | ✅ | wrangler 或 API |
| 双部署同步（GitHub Actions） | ✅ | push 触发两边 |
| 自定义域名 | 🟡 | Cloudflare 支持，需配置 DNS |
| PWA（离线游玩） | 🟡 | manifest + Service Worker，单文件友好 |
| 版本回滚 | 🟡 | Cloudflare Pages 历史部署 |

**上限**：双平台自动部署 + 全球 CDN + 可选 PWA 离线。

## 4. 三档方案对比

基于功能全集，给出三档递进方案：

### 方案 A（轻量版）—— 基础玩法稳固

- 范围：渲染基础 + 三武器 + 波次 + 触屏 + 双部署
- 目标：能玩、能通关、能在线访问
- 工作量：约 1500 行
- 风险：低

### 方案 B（中等版）—— 玩法与反馈完善

- 范围：方案 A + 武器手感 + 敌人 AI + 战斗 UI（伤害数字/小地图/击杀提示）+ 设置面板
- 目标：手感接近商业手游，反馈丰富
- 工作量：约 2000 行
- 风险：中

### 方案 C（完整版）—— RPG 化深度体验

- 范围：方案 B + 存档系统 + 成就 + 升级树 + 性能护栏 + 可选 Boss/技能/天气
- 目标：单局可重复游玩，长期进度驱动，接近独立游戏品质
- 工作量：约 2500-3500 行
- 风险：中高（单文件维护复杂度上升）

## 6. 单页理论上限结论

在「单 HTML + CDN Three.js + 无后端 + 移动端优先」的硬约束下，**理论上限**为：

> **一款单机 PVE 波次生存 FPS，具备体素世界、完整武器库、FSM 敌人 AI、RPG 化进度系统（存档/成就/升级）、双端原生输入、双平台 CDN 部署，视觉与玩法深度接近独立游戏品质，但无法实现真多人联机与云存档同步。**

具体边界：

- ✅ **可达**：体素世界 + 昼夜 + 三武器 + 手雷/近战/TNT + FSM AI + 波次 + 完整 HUD + 伤害数字 + 小地图 + 计分板 + 设置 + 存档 + 成就 + 升级树 + 双端触屏 + 双部署
- 🟡 **可做但需权衡**：Boss 战、技能系统、天气、BGM、后处理、PWA、本地排行榜、i18n、手柄
- 🔴 **不可达**：真多人联机、云存档、跨设备同步、光线追踪、语音识别

**结论**：方案 C 完成后，本项目将达到单页 FPS 的理论上限，剩余空间主要集中在内容扩展（更多敌人/武器/Boss）与体验打磨（PWA/i18n），而非架构能力突破。
